# コードレビュースキル (Code Review)

このスキルは、コードの変更差分または特定ファイルを対象として、高品質かつ実用的なコードレビューを実施するための手順書です。

---

## ワークフロー手順

### ステップ 1: レビュー対象の特定と差分の取得

1. **ユーザー指定の確認**:
   - 特定のファイルやコミット、ブランチが指定されているか確認します。
2. **差分・対象コードの取得**:
   - **未コミット変更（ワーキングツリー / ステージング）の場合**:
     `git status` および `git diff` / `git diff --cached` を実行して差分を確認します。
   - **ブランチ間差分の場合**:
     `git diff main...HEAD`（または指定のブランチ）を実行します。
   - **特定コミットの場合**:
     `git show <commit-hash>` を実行します。
   - **特定ファイルの場合**:
     対象ファイルを `view_file` で閲覧します。

### ステップ 2: プロジェクトコンテキストと規約の確認

1. **プロジェクト固有の指示・制約の確認**:
   - ルートや関連ディレクトリの `AGENTS.md` / `GEMINI.md` に記載されたルール（言語仕様、フレームワーク規約など）を確認します。
   - 例: Next.js のバージョン差異、非推奨 API の使用禁止など。
2. **関連コードの確認**:
   - 変更されたコンポーネントや関数が参照している型定義や共通ユーティリティを必要に応じて確認します。

### ステップ 3: 多角的な観点での分析

[観点別チェックリスト](./references/checklist.md) を参照し、以下の項目を重点的に検証します。

1. **正確性・堅牢性 (Correctness & Robustness)**:
   - 要件の充足、エッジケース、境界値、null/undefined 安全性、非同期・エラーハンドリング。
2. **セキュリティ (Security)**:
   - 秘密情報・APIキーの漏洩、入力値検証、XSS、インジェクションリスク。
3. **設計・可読性・保守性 (Architecture & Clean Code)**:
   - 単一責任、DRY、命名規則、不要なネスト、関心の分離。
4. **パフォーマンス (Performance)**:
   - 不要な再レンダリング、重い計算処理、メモリリーク、重複フェッチ。
5. **フレームワーク・言語固有観点**:
   - Next.js（App Router、Server/Client Components 境界、Hooks 依存配列など）、TypeScript（型安全性）。

### ステップ 4: レビュー結果の作成と出力

[レビュー出力テンプレート](./references/output_template.md) に沿って、日本語で構造化されたレポートを出力します。

- **概要サマリー**:
  - 対象ファイル / コミット
  - 変更概要
  - 総合判定（✅ **Approved** / ⚠️ **Changes Requested** / 💬 **Comment**）
- **重要度別指摘事項**:
  - 🚨 **Critical**: 重大なバグ、セキュリティホール、データ損失リスク
  - ⚠️ **Warning**: 潜在的バグ、パフォーマンス問題、設計上の懸念
  - 💡 **Suggestion / Nitpick**: 可読性向上、リファクタリング、より良い書き方
  - 👏 **Positive**: 優れた実装、良い工夫
- **具体的な改善コード提案**:
  - ファイルパスと該当行番号（`file:///` リンク）
  - Before / After コードスニペット
  - 修正理由とメリット

### ステップ 5: 次のアクションの提案

レビュー結果を提示した後、以下の対応をユーザーに提案します:
- 指摘した修正点について、エージェント側で自動適用（修正コミット等の作成）を行うかの確認。
- 疑問点や設計上の判断についてディスカッションを進める。

---

## 重要な注意事項

- **Web動作確認の禁止**: ユーザー指示に従い、WEB上での動作確認（ブラウザ起動や外部サイトアクセス）は行わず、コード静的解析および差分分析でレビューを完結させます。
- **建設的なトーン**: 単に問題点を列挙するだけでなく、理由と具体的な解決コードスニペットを提示し、優れた実装点（Positive）も適切に評価します。
- **ファイルリンク**: レビュー内のファイル参照には Markdown のリンク形式（`[filename](file:///path/to/file#L1-L10)`）を使用します。

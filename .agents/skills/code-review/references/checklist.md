# コードレビュー観点別チェックリスト

本チェックリストは、コードレビューを実施する際に確認すべき主要な評価基準をまとめたものです。

---

## 1. 正確性・堅牢性 (Correctness & Robustness)
- [ ] **要件とロジック**: 意図された機能要件を満たしているか？ 仕様の取り違えはないか？
- [ ] **境界値・エッジケース**: 配列の空要素、0、負数、極大値、境界条件でのオフバイワンエラー等に対応できているか？
- [ ] **null / undefined 安全性**: オプショナルチェーン（`?.`）や Null合体演算子（`??`）を適切に使用し、ランタイムエラー（`TypeError: Cannot read properties of undefined` など）を防いでいるか？
- [ ] **非同期処理・例外処理**: `async/await` に対応する適切な `try-catch` やエラーバウンダリが存在するか？ Promise の未捕捉エラー（unhandled rejection）が発生しないか？
- [ ] **リソースの解放**: イベントリスナー、タイマー（`setTimeout`, `setInterval`）、AbortController などがコンポーネントのアンマウント時に適切に破棄・クリーンアップされているか？

---

## 2. セキュリティ (Security)
- [ ] **秘密情報の保護**: APIキー、アクセストークン、パスワード、接続文字列がソースコードにハードコードされていないか？（`.env` 等に退避されているか）
- [ ] **インジェクション脆弱性**: SQL、NoSQL、OSコマンド、LDAPなどのインジェクションリスクがないか？
- [ ] **XSS (クロスサイトスクリプティング)**: ユーザー入力がサニタイズされずに HTML / DOM に埋め込まれていないか？（`dangerouslySetInnerHTML` などの使用箇所は安全か）
- [ ] **入力値バリデーション**: フロントエンド・バックエンドの双方で適切なバリデーション（zod, yup など）が行われているか？
- [ ] **認証・認可**: 保護されたルートや API エンドポイントでセッション・ロール検証が適切に行われているか？

---

## 3. 設計・可読性・保守性 (Architecture & Clean Code)
- [ ] **単一責任の原則 (SRP)**: 1つの関数・コンポーネント・モジュールが過剰な責務を抱え込んでいないか？
- [ ] **DRY (Don't Repeat Yourself)**: 意味のある共通処理が重複コードとして散らばっていないか？（ただし過剰な共通化・早すぎる抽象化にも注意）
- [ ] **命名の明確さ**: 変数・関数・型・クラスの名前がその役割を正確に表しているか？ 不自然な略語や曖昧な名前はないか？
- [ ] **関心の分離**: UIレンダリング、状態管理、ビジネスロジック、データフェッチが適切に分離されているか？
- [ ] **コードの平易さ**: ネストが深すぎないか？ 早期リターン（Early Return）を活用して可読性を高められるか？

---

## 4. パフォーマンス (Performance)
- [ ] **不要な再レンダリング**: React で無駄なステート更新や親コンポーネントからの不要なプロパティ再生成が発生していないか？（`useMemo`, `useCallback` の適切な活用）
- [ ] **計算量**: ループ内の不要な反復処理、`O(n^2)` 以上の非効率な探索・操作がないか？（`Map` / `Set` の活用）
- [ ] **データ取得・通信効率**: N+1 クエリや同一データの重複リクエストが発生していないか？ キャッシュ機構が活かされているか？
- [ ] **バンドルサイズ・遅延ロード**: 重複した大型ライブラリのインポートがないか？ Dynamic Import や遅延読み込みが検討されているか？

---

## 5. Next.js / TypeScript 特有の観点
- [ ] **Server / Client Component の境界**: `'use client'` ディレクティブは必要最小限のコンポーネントに限定されているか？ 可能な限り Server Component で処理されているか？
- [ ] **Hooks の依存配列**: `useEffect`, `useCallback`, `useMemo` などの依存配列（`deps`）に抜け漏れや不要な値が含まれていないか？
- [ ] **Next.js の規約と最新仕様**: `app` ディレクトリ（App Router）の規約に従っているか？ 非推奨（Deprecated）の API を使っていないか？
- [ ] **厳格な型定義**: `any` 型の安易な使用を避け、適切なジェネリクスやユニオン型で型安全性が保たれているか？

---

## 6. プロジェクト固有規約
- [ ] リポジトリ内の `AGENTS.md` や `GEMINI.md` に定義された規約（言語設定、ライブラリバージョンのルール等）を遵守しているか？
